# Insulator AI V5 — Modular Web Prototype

ต่อยอดจาก V4 โดยคง IndexedDB, ประวัติ, แผนที่, GPS, Firebase Authentication และการซิงก์แบบกดเอง

## เปิดใช้งาน

1. แตกไฟล์ ZIP โดยคงโฟลเดอร์ทั้งหมดไว้
2. นำไฟล์และโฟลเดอร์ภายใน `InsulatorAI_V5` ขึ้น **GitHub Pages** (ต้องมี index.html ที่ root ของ site/repository)
3. เปิดเว็บผ่าน HTTPS และอนุญาต GPS หากต้องการใช้ตำแหน่งปัจจุบัน
4. สร้างหรือเลือกโครงการ → กรอกรหัสเสา → ระบุจำนวนลูกถ้วยตามจริง → เลือกลูกถ้วย → เลือกรูป → ทดลอง DEMO → บันทึก
5. เข้า Settings เพื่อล็อกอินและกดอัปโหลด/ดาวน์โหลดจาก Firebase (ระบบยังไม่ซิงก์อัตโนมัติ)

ไฟล์ `index.html` เปิดด้วย `file://` อาจทำให้ Firebase/GPS/CORS ใช้งานไม่ครบ แนะนำเว็บไซต์ HTTPS

## โครงสร้าง

- `index.html`: หน้าจอทุกหน้า (ยังคงองค์ประกอบ HTML ของ V4 เพื่อรักษาฟังก์ชันเดิม)
- `css/base.css`: CSS เดิมจาก V4
- `css/v5.css`: ธีม V5/หน้ารายละเอียดเสา
- `js/core.js`: IndexedDB/ประวัติ/การตรวจสอบ/GPS/แผนที่จาก V4
- `js/projects.js`: โครงการ ตัวกรอง ค้นหาประวัติ/ส่งออก
- `js/firebase.js`: Auth, Firestore, ส่ง/ดึงข้อมูลเอง
- `js/v5-data.js`: ระบบเสาและลูกถ้วยรายลูกและประวัติย้อนหลัง
- `js/v5-ai.js`: DEMO หรือ YOLO API adapter
- `js/bootstrap.js`: เริ่มต้นแอป
- `docs/API.md`: รูปแบบ JSON/การเชื่อมต่อโมเดล

## การเก็บข้อมูล

- ประวัติภาพเก่าอยู่ใน IndexedDB ชื่อ `InsulatorAIDatabaseV3` เช่น V4 โดยไม่ลบข้อมูล
- โครงการเดิมอยู่ที่ `INSULATOR_SURVEY_PROJECTS_V1`
- เสาและจำนวนลูกถ้วยของ V5 อยู่ที่ `INSULATOR_V5_POLES_V1`
- Cloud ยังคงอยู่ภายใต้ `users/{uid}`: `projects`, `inspections`, `poles` (เฉพาะบัญชี ไม่ใช่โครงการที่แชร์ข้ามบัญชี)
- รูปภาพยังอยู่ในเครื่อง ไม่ถูกส่งขึ้น Firestore / Firebase Storage
- การดาวน์โหลดจาก Cloud เป็นการ **เพิ่มรายการใหม่** ไม่ลบหรือแก้ไขรูปภาพเดิมในเครื่อง
- การแก้จำนวนลูกถ้วยไม่ลบประวัติเดิม และรายละเอียดเสาแสดงเฉพาะหมายเลขปัจจุบัน ส่วนประวัติเก่ายังคงอยู่

## ข้อจำกัดที่ต้องทำต่อ

- AI เป็น DEMO โดยค่าเริ่มต้น; โหมด API ต้องมีเซิร์ฟเวอร์และโมเดลจริง พร้อม postprocessing
- ยังไม่มีระบบแชร์โครงการระหว่างหลายบัญชี / กฎสิทธิ์สมาชิกโครงการ
- ต้องทดสอบการใช้งานบน iOS/Android จริง และทดสอบ Firestore Rules กับฐานข้อมูลจริง
- ระบบตรวจสอบนี้เป็นต้นแบบ ไม่ควรใช้ผล DEMO ตัดสินใจบำรุงรักษา
- จำนวนลูกถ้วยต่อเสาใน UI จำกัด 1–500 เพื่อป้องกันการสร้างองค์ประกอบจำนวนมาก (ไม่ใช่ข้อจำกัดทางไฟฟ้า)
- โค้ด V4 ถูกแยกเป็นโมดูลตามหน้าที่ แต่ยังใช้ global functions เพื่อรักษาความเข้ากันได้; สามารถย้ายต่อไปเป็น ES modules ในเฟสถัดไป
